# M0 — 架构验证

[English](M0.md) · 简体中文

M0 是必须先完成的架构验证阶段。以下门槛获得可复现的证据前，不实现完整界面、认证产品或生产 Compose。

远端运行记录和剩余阻塞见 [M0 验证与决策](M0-evidence.zh-CN.md)。

## 门槛 A — DSH Runtime 与插件持久化

1. 根据上游元数据选择确切的官方 DSH npm 版本，不假定此前讨论的版本仍是最新版。
2. 核查该 DSH 版本的运行环境要求、CLI 命令、Profile 路径、Plugin Manager API 和启动行为。
3. 构建一次性的 Runtime 原型镜像，包含 Node、pnpm 和工具链。DSH 包必须在运行时装入持久化卷，不能打进镜像。
4. 用官方 CLI 创建 Web Profile。
5. 安装已知安全的 npm 测试插件或 Bundle；如果上游支持，也装一个固定 Git 提交的插件。
6. 核对 Profile 的 package.json、锁文件、Bundle 清单、node_modules 链接和 pnpm Store 路径。
7. 重建容器，不重装插件，验证插件仍能激活。
8. 在独立目录安装第二个确切的 DSH 版本，切换、验证，再切回。
9. 测试 Profile 依赖是否仍兼容，记录迁移行为和回滚限制。
10. 用非 root UID 测试一个有代表性的原生依赖构建。

验收：

- 官方 DSH 包从持久化的 Runtime 路径运行。
- 至少两个确切的 DSH 版本共存。
- 切换无需重建镜像或覆盖已装版本。
- 重建容器后插件仍保留。
- pnpm Store 和锁文件完整保留。
- Runtime 管理器不就地修改活动版本。
- 记录不受支持的插件或系统依赖。

## 门槛 B — LinuxServer Chromium、Selkies 与 CDP

1. 核查 LinuxServer Chromium 官方当前文档和所选镜像的确切启动脚本。
2. 查阅 registry 元数据后固定已发布的镜像标签和摘要，不虚构标签。
3. 启动一个带 Selkies 的 Chromium 容器，持久化 `/config`。
4. 验证实际进程命令行包含 CDP 参数和专用的持久化 user-data-dir。
5. 从私有 Docker 网络中的对等容器验证 CDP 的 `/json/version` 和 `/json/list`。
6. 验证 CDP 未发布到宿主机或公网接口。
7. 人工通过 Selkies 打开页面；使用 Playwright 经 CDP 连接已有默认上下文。
8. 验证 Selkies 能看到 Agent 打开的页面，CDP 能列出人工打开的页面。
9. 验证人工和 Agent 共享测试站点的 Cookie。
10. 重启 Chromium，验证浏览器配置目录持久化。
11. 验证 Selkies 经 Traefik 在同源 `/browser/` 可用，路径前缀保留、WebSocket 正常，iframe 的 CSP 仅允许 DSH 源嵌入。

验收：

- 证明确实共享一个浏览器进程和配置目录。
- 人工和 Agent 能看到相同的标签页和已登录状态。
- CDP 留在私网。
- Selkies 子路径路由和 iframe 在确切的固定镜像版本上可用。
- 记录不受支持的浏览器操作或 Playwright CDP 限制。

## 门槛 C — 独占输入控制可行性

这是宣称实现独占模式前必须通过的门槛。

1. 确认固定版本的 Selkies 如何注入键盘和鼠标事件。
2. 确认能否禁用人工输入同时保留视频。
3. 实现一次性实验，在 Agent 持有租约时拦截 Selkies 输入。
4. 验证没有有效租约的 Agent CDP 命令会被拒绝。
5. 验证租约过期、接管、浏览器断开、DSH 重启和并发请求。
6. 验证过时租约代次无法继续发出命令。

验收：

- Agent 租约从实际输入边界阻止所有人工输入，只隐藏控件不算。
- 人工持有控制权时，服务端拒绝 Agent 工具操作。
- 接管先停止接收新操作，安全等待或取消仍在运行的操作，然后开放人工输入。
- 故障时默认进入安全状态。
- 若拦截 Selkies 输入需要维护自定义浏览器镜像或代理，报告取舍，请求决策后再推进。

## 门槛 D — DSH 扩展 API 可行性

1. 查看所选 DSH 版本源码和文档，确认右侧栏标签注册、浮动和停靠、保留挂载、插件生命周期以及 Browser Use Provider 扩展点。
2. 实现最小插件原型，注册标签页并嵌入同源测试 iframe。
3. 验证浮动、停靠、调整大小、最大化和 iframe 生命周期。
4. 验证能否通过受支持的扩展点封装或拦截 Browser Use，而不 Fork DSH 核心。
5. 如果没有受支持的工具拦截钩子，记录独立 Provider 方案。

验收：

- 不 Fork DSH 核心。
- 采用受支持的公开扩展 API。
- iframe 在切换标签页和浮动生命周期中按要求保留。
- 浏览器调用能在执行 CDP 前受控。

- DSH 插件 API 可行性报告。
