## Transactional upgrade and recovery (#8)

`dsh-runtime upgrade` replaces the hand-sequenced `install` + `select` pair for a version change. It installs the candidate beside the active version, runs the compatibility gate and a readiness probe against a copy of DSH_HOME, records a fingerprint of Profile state, writes an archive plus manifest, and only then moves the selection pointer.

| Check | Observed |
| --- | --- |
| Gate on real installs | 591 packages scanned for `0.2.2-rc.1` and 598 for `0.2.2-rc.5`; 30 declared lifecycle scripts in each. These are upstream and reported, not blocking, because the install policy is fixed at `--ignore-scripts`. |
| Real Bundle constraint | The shipped browser Bundle declares `engines.dsh` `0.2.2-rc.1` and peer `@deepseek-ai/dsh-mcp-client` `0.2.2-rc.1`, so rc.5 is blocked while it is installed. This is a real limitation, not a test artifact. |
| Archive scope | Excluding `runtime` and `pnpm` took a measured 223 MB archive to 2.2 KB for the same 40 KB Profile; both excluded trees are reinstallable. |
| Recovery refusals | A tampered archive, a missing manifest, a backup whose DSH version is not installed, and an approval that is a range or a suffixed version are all refused without touching live state. |

Pointer rollback and data restore are separate operations, and `verify` decides which is required by comparing Profile manifests, lockfiles and pnpm-store package versions against the state recorded before the switch.

### Not yet verified

- No installed DSH release was known to migrate Profile or plugin data; the real drill switch reported `unchanged`. Migration detection and restore are proven by a synthetic lockfile change, so DSH's own migration behaviour remains unproven until such a release exists.
- The gate reports upstream lifecycle scripts but cannot prove none of them was needed at runtime; the readiness probe is the actual defence.
- The drill runs the preview composition, which does not enable the browser Bundle. Upgrading a deployment that has the Bundle installed is blocked by its `engines.dsh` pin until a matching Bundle ships.

## Configurable subnets and overlap preflight (#9)

The two Compose subnets and every address inside them were constants. `deploy/network.sh` is now the single source: it derives the subnet definitions, the dynamic `ip_range`, each static address, the provider's bind addresses, the health-check destination and the Runtime certificate SAN from `WORKSTATION_SUBNET` and `BROWSER_SUBNET`. Defaults reproduce the previous values, so an existing deployment does not move.

| Check | Observed |
| --- | --- |
| Defaults preserved | All 22 `${VAR:-default}` entries in both Compose files equal the derived value; a mismatch would move a deployment that upgrades without setting anything. |
| Custom plan | On `10.71.241.0/24` + `10.71.233.0/24` the stack ran fully: `Runtime 10.71.241.2, Provider 10.71.241.3/10.71.233.2`, with the browser, Auth, backup/restore and MCP lease checks all passing. |
| Rejection cases | Host-bit CIDRs, prefixes outside `/16`..`/28`, non-CIDR strings, overlapping workstation/browser subnets, and a plan covering the CI proxy network are all refused before anything is created. |
| Conflict diagnosis | A host route and an existing Docker network each fail the preflight, naming the conflicting CIDR and stating that neither network was created or changed. The default route is excluded on purpose. |
| Repeat initialization | Re-running on an existing state directory keeps the internal CA, the Runtime certificate and every shared secret byte-for-byte; only the derived keys are rewritten. |
| Subnet change | Refused without `--reissue`; with it, the CA and certificate are replaced for the new address while the other secrets survive. |

Three defects surfaced only because CI ran the real stack:

1. `${...}` inside a YAML flow mapping (`{ipv4_address: ${...}}`) does not parse, which failed all four legs at once.
2. The provider image bound `172.30.241.3` from a constant in `prototypes/m0/provider/server.mjs` and died with `EADDRNOTAVAIL` on a custom plan.
3. Auth reached the provider's control listener at a literal address as well.

Each now has a regression check that was verified by reintroducing the defect.

### Not yet verified

- Changing subnets on an existing deployment is a lossy migration: containers must be recreated and Traefik reconnected to the new networks. The steps are documented but have not been rehearsed on a real host.
- The preflight has only met GitHub-runner route tables, which are clean. A real VPN route table is the case it exists for and is still unproven.
- `--reissue` replaces the internal CA. Services that pinned the old CA must be recreated; this is stated in the documentation but not exercised end to end.

## Exclusive browser input and safe handoff (#4)

Agent browser control was disabled because a mouse button held at handoff survived the whole Agent lease. The cause is an ordering property of the pinned Selkies, not a UI gap: input authority is evaluated per frame against the live token table (`websockets_mode.py:6235`), and `provision_tokens()` installs a new table *before* it announces the change (`:8071-8072`, `:8356`). A release frame sent after a revocation is dropped like any other input frame, so only a release issued *before* the flip can land.

`browser-gate` (ADR-0005) is the WebSocket peer in front of the data socket and owns that transition. It releases with Selkies' own `reset_keyboard()` and `release_mouse_buttons()` primitives, ordered before the Provider flips the table, and proves dispatch with a PING/PONG barrier on the same connection.

| Check | Observed |
| --- | --- |
| The original defect reproduces | Against a fake Selkies that enforces the real ordering, flipping the table first and then sending the page's release leaves `{keys:[97], buttons:1}` held. The test fails if this ever stops being true, so the regression it guards cannot silently disappear. |
| The gate releases first | After `POST /handover` returns `200`, the fake desktop holds `{keys:[], buttons:0}`. |
| Input is refused while authority is gone | Frames the page sends after the revocation never reach the desktop. |
| Release does not depend on gate bookkeeping | A key the gate never forwarded is still released, because the release is unconditional rather than replayed from a tracked set. |
| A grant during a release is refused | Authority returning mid-handover never reopens input, which is the interleaving M0 recorded. |
| Hand-back is explicit | A late `MK_ACCESS,1` alone does not reopen input; only an authenticated `/resume` does. |
| Unprovable release fails closed | With the upstream refusing to answer PING, `/handover` returns non-`200`, `released:false`, and the gate stays `CLOSED`. |
| An unproven release is not forgotten | After a barrier timeout the refusal outlives the connection: neither an idle gate nor a reconnected page that has not been granted authority will report a release, because the desktop's held state is global and unknown. A later handover that proves a release clears it. |
| A revoked socket cannot claim a release | `/handover` on a socket that has lost authority is refused. The barrier would otherwise confirm dispatch while `websockets_mode.py:6235` dropped the frames, which is a false success in exactly the case the gate exists for. |
| A page that speaks first is not dropped | The page sends `SETTINGS` the moment its socket opens, which can beat the gate's own upstream connection. Frames are queued until upstream opens; the regression test forces the order and fails against the previous behaviour. |
| The gate is not the authority | The operator's handshake is forwarded with `Host`, `Origin` and the session-token subprotocol intact, so Selkies still authorises the socket itself. |
| Control API is authenticated | A wrong or malformed bearer is refused on every state-changing route. |
| Only the data socket is proxied | A non-data-socket path is refused rather than proxied. |

The barrier choice is worth recording because the obvious alternative looks right: a pointer echo cannot serve as the completion barrier, since the echo is suppressed when the pointer is already drawn where it was (`input_handler.py:2013-2016`), and a zero-delta release leaves it exactly there. It would be silent in precisely the held-drag case the barrier exists for.

### Not yet verified

- The gate has not run against a live Selkies instance. The ordering and the PING/PONG barrier are argued from the pinned source, not measured.
- The full transition matrix on a real host — HUMAN→AGENT, AGENT→HUMAN, lease expiry, client disconnect, Chromium restart, concurrent input during handoff, Provider abnormal exit — is the gate's acceptance test and has not been run. Agent browser control stays disabled until it passes.
- The container-level checks run in CI only; this environment has neither Docker nor Go.

## Public follow-up

Keep the preview bound to loopback. Public access requires Go/SQLite ForwardAuth, HTTPS, and an operator deployment target. The Browser Provider connects through official MCP. The initial handoff assumes the operator finishes input and transfers control explicitly. Held input and the native Sidebar remain open.
