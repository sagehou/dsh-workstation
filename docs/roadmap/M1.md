# M1 — Runtime and first private bring-up

English · [简体中文](M1.zh-CN.md)

[M0 evidence](M0-evidence.md) supports promoting the Runtime and its version manager. Ship the shortest usable slice first: official DSH Web and manual Selkies at one loopback origin, reached from another machine through an SSH tunnel. Keep the Runtime, workspace and Chromium data in separate volumes. A fresh install selects an exact DSH distribution; changing the bootstrap version does not update an existing server.

The first delivery uses the M0 pins: Node 24.22.3, pnpm 11.28.5, DSH 0.2.2-rc.1 (switch and rollback also exercised 0.2.2-rc.5), LinuxServer Chromium and Traefik by digest. The [GitHub-hosted run at `fe91e89`](https://github.com/sagehou/dsh-workstation/actions/runs/44474103563/job/135390351014) passed `bash deploy/ci-preview.sh`. It observed an unauthenticated DSH 401, an authenticated boot page and `/browser/` HTML through the same loopback Traefik port. It also exercised the offline maintenance lock, a refused selection, a successful version switch and rollback, and workspace persistence after container recreation without an image rebuild. It uploaded the [loadable Runtime image and logs](https://github.com/sagehou/dsh-workstation/actions/runs/44474103563/artifacts/14505771617).

The private preview is ready to deploy using the [bring-up guide](../../deploy/README.md). No deployment to an operator host is recorded.

The public launch still needs the Go/SQLite ForwardAuth service from ADR-0003, an HTTPS origin, and an operator deployment target. The private Compose file must never bind to a public interface. The Browser Provider follows as a separate integration with DSH over official MCP. Limit the initial handoff to one user finishing their input and transferring control explicitly. Carry forward the held-input finding and wait for the official Sidebar lifecycle APIs.
