# M0 实验设计

[English](M0-design.md) · 简体中文

范围：[Issue #1](https://github.com/sagehou/dsh-workstation/issues/1)。只在一次性远端运行器上执行，使用全新 Compose 卷，不使用 DeepSeek 凭据。M0 实验在独立于 `main` 的分支开展。任何实验夹具都不直接用于生产。

- **A：** 使用一个固定版本的 Node/pnpm 镜像、一个非 root UID 和一个 DSH_HOME 卷。将确切的 DSH 版本装到独立目录，安装和激活时持锁。检查经过认证的 Web 启动响应和 Profile 状态；有意让一次就绪检查失败，确认指针还原。重建容器但不重装，再检查 Store、清单、锁文件、包链接及 Bundle 运行时的可观测结果。依赖生命周期脚本的验证结果单独记录。
- **B：** 用摘要固定已发布的 LinuxServer 镜像。Chromium 桌面的 CDP 监听回环地址；在同一网络命名空间测试中继，只绑定专用私网接口。远端运行器执行观察和 Playwright CDP 连接。Traefik 路由 Selkies 时保留前缀。检查实时操作、标签页和 Cookie 是否一致、浏览器配置目录持久化，以及上游响应头和传输方式。
- **C：** 设计租约实验前，先查看固定版本 Selkies 安全模式的令牌表及 DSH 的公开工具守卫。Agent 请求派发时，人工须失去控制权但保留视频。工具守卫只解决一部分所有权问题：能执行任意 shell 命令的 DSH 进程不能有其他路径直连 CDP。没有架构决策前，不为拦截输入构建自定义镜像或代理。
- **D：** 审查发布的侧栏、客户端模块和 Browser Use 契约。注册、浮动和保留 DOM 的测试无法替代缺失的原生操作。不修改 DSH 核心，也不导入 dockkit 私有接口。

获批的 C 门槛后续实验使用一次性浏览器 Provider，作为隔离 CDP 网桥唯一的客户端。DSH 通过官方 ACP 会话接口获得范围受限的 Streamable HTTP MCP 声明。使用受支持的有状态 MCP 版本：每个一次性传输凭据标识独立客户端，MCP 事件流中断时撤销其租约。授权和接管走独立控制网络。请求分派前检查在线连接、代次和过期时间。唯一的工具在 Chromium 已有上下文中的固定测试标签页写标记。测试用同步点挂起一次真实浏览器操作，同时尝试竞争调用或交接并发送 Selkies 输入。如果断线导致无法判断操作是否完成，保持锁定，更换 Chromium 进程后才恢复输入。使用一次性卷和密钥，不增加 DSH API，不改侧栏，不实现产品功能。

证据写入 M0 报告，链接运行器记录和命令。不打印启动认证 URL、令牌或 Cookie。失败或尚未检查的项目要明确记录。
