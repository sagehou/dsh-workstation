# DSH Web Workstation 产品规格

[English](SPEC.md) · 简体中文

状态：产品方向已批准；技术假设仍需通过 M0 验证。

## 1. 产品

自托管的 Web 工作台。保留官方 DSH 应用及插件生态，增加可远程访问的共享浏览器、认证网关和运维管理能力。

## 2. 用户和范围

- 初期供一位可信用户使用。
- 认证数据模型允许少量账号（2 至 5 个）。
- v1 不提供多用户隔离。只有将 DSH_HOME、工作区和浏览器配置目录分别隔离后，才能把多个通过认证的用户视为相互隔离的租户。
- 优先支持桌面浏览器；移动浏览器需基本可用。
- 通过 Docker Compose 部署，使用单一公网源。

## 3. 产品需求

### 3.1 DSH Runtime 和版本管理

- 基础 Docker 镜像包含兼容的 Node.js、固定版本的 pnpm、Git/SSH、CA 证书和常见 Node 原生依赖的构建工具链。
- 在运行时把官方 DSH npm 包安装到持久化数据卷。
- 用户可以查询可用 npm 版本、安装指定版本、保留多个版本、选择版本、更新、验证及回滚。
- 版本切换具备事务语义，绝不覆盖已安装版本。
- Runtime 镜像版本独立于 DSH npm 版本。
- 安装或健康检查失败必须保留先前的活动版本。
- 切换前验证 DSH 与 Node 的兼容性；有元数据时也验证已装插件的兼容性。
- 切换 DSH 版本时不自动修改 Profile 依赖。
- 数据迁移或依赖操作前备份 DSH_HOME。

### 3.2 插件生态和持久化

- 保留官方 DSH Profile 和 Plugin Manager 的行为。
- 支持 npm 包、固定版本、Git HTTPS、固定 Git 提交、上游支持的本地包路径、ESM/CommonJS 和常见原生模块构建。
- 在同一持久化文件系统内保存 DSH_HOME，包括 Profile 包清单、锁文件、node_modules 链接和文件、pnpm Store、Bundle 清单、设置、凭据、会话和插件配置。
- 工作区与 DSH_HOME 分开。
- 界面区分已安装、已启用、兼容性和运行健康状态。
- 审查 pnpm 构建脚本及原生依赖；不得全局允许任意安装脚本。
- ffmpeg、libvips 等特殊系统依赖可能需要可选服务或有文档的主机、Runtime 扩展。不能在缺少系统前置依赖时承诺所有第三方插件都能运行。

### 3.3 共享 Chromium 和 Selkies 浏览器

- 使用 LinuxServer Chromium 镜像，不把 Chromium 或桌面栈放进 DSH Runtime。
- 人工和 Agent 共享同一个 Chromium 进程及同一份持久化浏览器配置目录。
- 人工通过同源的 `/browser/` 使用 Selkies 界面。
- 在上游支持的情况下，Agent 通过官方 DSH Browser Use/Playwright MCP 扩展，用 CDP 连接同一个 Chromium。
- 浏览器不使用独立域名或独立登录。
- CDP 不得发布到宿主机或公网接口，限制在私有 Docker 网络及服务边界内。
- 浏览器配置和下载文件需持久化。
- 浏览器重启或断开时可见，且能够重新连接。
- 独占控制有 HUMAN、AGENT、HANDOVER、PAUSED、DISCONNECTED 五种状态。服务端必须验证租约。Agent 持有控制权时拦截人工输入；人工持有控制权时拒绝 Agent 工具调用。
- 接管时先停止接收新的 Agent 操作，安全完成或取消进行中的操作，撤销租约，再开放人工输入。
- Selkies 如果无法可靠拦截人工输入，此需求即未达成；不能用界面锁模拟。

### 3.4 Workstation 界面插件

- 使用固定 DSH 版本支持的客户端插件和右侧栏 API。
- 在右侧栏增加浏览器桌面标签页。
- 使用 DSH 原生面板生命周期 API，实现停靠、浮动、调整大小、最大化和还原、隐藏、重连及状态显示。
- 如果上游支持，切换标签页或隐藏时保留 iframe 挂载。隐藏不得终止 Chromium。
- 浏览器 iframe 使用同源相对路径 `/browser/`。
- 明确展示人工或 Agent 控制状态、控制者、任务状态和接管操作。
- 不重新实现 DSH 的主聊天、会话、文件、差异对比或终端界面。

### 3.5 认证网关

- 独立 Go 服务，使用 SQLite WAL。
- 密码哈希使用 Argon2id。
- TOTP 遵循 RFC 6238。账号必须绑定 TOTP，密码登录时有独立的 TOTP 步骤。
- TOTP 登录界面：第一屏只有用户名和密码；密码验证成功后，切换到只有 TOTP 输入框的独立第二屏或弹窗。不要同时显示密码和 TOTP 字段。
- Passkey 使用 WebAuthn，严格核对配置的 RP ID 和 HTTPS 源，要求用户验证，使用一次性挑战，支持每位用户的多个凭据。
- Passkey 可以作为独立登录流程，不隐式等同于密码加 TOTP。修改敏感账号设置前须再次验证身份。
- 恢复码只能使用一次，以哈希保存，只展示一次；重新生成会使旧恢复码失效。
- 会话使用不透明的安全随机令牌，只存储令牌哈希。支持配置空闲超时、绝对时限和最大会话数，支持单个或全部撤销。
- Cookie：`__Host-dsh_session`，带 Secure、HttpOnly、SameSite=Lax、Path=/，不设 Domain。
- 认证端点和 ForwardAuth 校验端点不得受自身 ForwardAuth 中间件保护。
- ForwardAuth 保护 DSH 和 `/browser/`。未认证的 API 或 WebSocket 请求应返回 401 或拒绝升级，不能返回 HTML 登录页。
- 审计登录成功或失败、MFA 变更、凭据变更、会话变更和账号停用或恢复。
- 限流、CSRF 防护、源校验、防账号枚举和安全的密钥管理。
- 初始化只能执行一次，创建初始管理员后关闭。

### 3.6 路由和部署

- 使用单一源：`https://<host>/`。
- DSH 位于 `/`。
- Selkies 位于 `/browser/`，采用 LinuxServer 支持的子路径配置，由 Traefik 保留前缀。除非上游文档明确要求，否则不使用 StripPrefix。
- 认证界面与 API 位于 `/_auth/`。
- 浏览器控制 API 仅供内部访问或要求认证，不得成为无需认证的公网管理入口。
- Traefik ForwardAuth 用同一个会话 Cookie 保护 DSH 和浏览器路由。
- Docker Compose 编排 DSH、认证服务和 Chromium。Traefik 可以是共享网络上的已有服务。
- 初期设计不引入 Authentik、Browserless、Redis、PostgreSQL、VNC、noVNC 或独立浏览器域名。

### 3.7 运维

- Runtime 镜像、DSH npm 包、认证镜像、Workstation 插件和 Chromium 镜像独立版本化。
- 生产部署固定版本标签及摘要。
- 为 DSH_HOME、工作区、Chromium 配置目录、认证数据库及加密密钥提供备份恢复。
- 恢复测试须证明 TOTP 和已注册的 Passkey 仍然可用。
- 健康检查验证实际就绪状态，进程存在本身不能证明就绪。
- 记录并测试升级回滚流程。

## 4. 使用体验

### 登录

1. 密码界面只有用户名和密码。
2. 密码正确后，服务端创建短期预认证挑战，切换到独立的 TOTP 界面。
3. TOTP 界面仅输入验证码，提供返回、重新开始和恢复码选项。
4. TOTP 成功后创建完整会话，只重定向到校验过的同源相对返回路径。
5. Passkey 是清晰可见的独立登录选项。

### 浏览器

- 右侧栏的浏览器桌面标签页。
- DSH 原生浮动和停靠生命周期。
- 完整 Selkies 界面。
- 显示人工或 Agent 状态及控制人。
- 清晰的接管和交还操作。
- 能重连，能看到断线状态。

### Runtime

- 当前版本、已安装版本、可用版本。
- 安装指定版本、激活、回滚、删除未激活版本。
- 兼容性报告、日志、备份及健康状态。

### 插件

- 已安装、市场或来源、更新。
- 显示来源、版本、DSH 兼容性、依赖和构建脚本批准状态。
- 通过官方 DSH Plugin Manager 安装、启用、停用、更新和删除。
- 展示操作日志，区分已安装、已激活、运行健康。

### 安全

- 修改密码、管理 Passkey、管理 TOTP、重新生成恢复码、列出及撤销会话、查看审计日志。
- 敏感设置变更要求再次验证身份。

## 5. 范围外

Windows Companion、多租户编排、Kubernetes 部署、自定义 Agent 运行时、自定义编辑器、公共插件市场托管及多个并行浏览器实例。

## 6. 完成标准

实现、自动化测试、配置文档、安全影响和故障恢复行为齐备，功能才算完成。容器启动不等于通过验收。
