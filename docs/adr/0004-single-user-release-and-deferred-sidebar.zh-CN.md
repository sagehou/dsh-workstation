# ADR-0004 — 首版严格单用户，原生 Sidebar 延后

**已接受 — 2026-11-23**

## 背景

项目已具备单用户 Compose 拓扑、自托管认证、共享 Chromium 浏览器和官方 DSH 集成。原产品规格允许 Auth 存在 2–5 个账户，同时又明确没有租户隔离；这会造成多个账户共用 DSH_HOME、工作区和浏览器配置的歧义。原生 Sidebar 也被列为目标工作台界面，但上游浮动/最大化/iframe 生命周期仍有未完成项。

## 决策

1. **首版严格只有一个本地管理员。** 初始化创建一个账户后永久关闭。没有用户创建、邀请、角色管理或第二个账户。同一管理员可以注册多个 Passkey。
2. **不提供多人共用模式。** 在 DSH_HOME、工作区、Chromium 配置、Provider 状态和密钥仍然共享时，不得增加第二个账户。未来多用户必须另行设计逐租户隔离架构。
3. **首版浏览器界面采用已认证的独立浏览器/控制页面。** 即使没有 DSH Sidebar，也必须完整可用并持续支持。
4. **原生 Sidebar 延后，不取消。** 后续只通过 DSH 公开 API 实现。不得 Fork DSH 核心、使用私有 DOM hook，或让首版发布依赖上游尚不支持的浮动/最大化行为。
5. **官方 DSH 保持产品核心。** 不另造 Agent Runtime、聊天/会话界面、编辑器、包管理器或公共插件市场。
6. **发布门槛以证据为准。** 较新 Traefik 版本上的 CI 通过不证明目标部署版本兼容。PR 合并也不能在缺少测试证据时自动关闭验收项。

## 后果

- Auth 保持为单管理员服务；从产品文档和界面计划中移除多账户歧义。
- 独立浏览器/控制页面是首版必需的产品入口和备用入口。
- Sidebar 可以在首个稳定部署之后继续开发，不阻塞首版。
- 首版只支持 Linux amd64 和单用户。多用户、租户编排和多个并行浏览器均不在范围内。
- 安全、浏览器交接、备份恢复和目标主机验证仍是发布门槛。
